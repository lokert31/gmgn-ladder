# Liquidity Ladder + GMGN

**[Гайд: как пользоваться](docs/GUIDE.md)** — установка, каждая функция по порядку, что делать, когда что-то не работает.

Расширение для Chrome. Две вещи в одном:

**График GMGN поверх Liquidity Ladder.** Открываешь пул — видишь свечи, а на
них свои ступени леддера, границы диапазона, глубину пула по уровням цены и
точки входа топ-холдеров. Окно двигается, масштабируется и прячется.

**Сторож.** Следит за ценой твоих позиций и сам собирает комиссии или
закрывает позиции — по пампу, у границы леддера или на уровнях, которые ты
задал. Вкладку сайта держать открытой не нужно: сторож заводит свои фоновые
вкладки в свёрнутой группе «сторож фисов». Но сам Chrome должен быть открыт.
Сбор на пампе можно выключить у отдельного токена: ⚙ → «Свои условия пампа по
токену» → выбрать токен → «не собирать на пампе». Порог, уровни и край леддера
по нему продолжат работать; вернуть — тем же переключателем на чипе.

**Карточка «LP» на GMGN.** Открыл токен — справа внизу разбор: сколько пулов
(люди / лесенки Liquidity Ladder / лаунчпад), сколько залили люди, объём и фисы
за час и сутки, доходность ликвидности у цены за последний час, риск по движению
цены и лучшие пулы для LP. Доходность считается по токену целиком: фисы на доллар
у пулов одного токена почти одинаковые — их выравнивает арбитраж.

**Пулы на графике GMGN.** Галка «на графике» в карточке LP: глубина всех пулов
токена полосами прямо на графике GMGN, с накопленными суммами от цены. Галка
«авторазбор» — считать карточку сразу при открытии токена или только по ⟳.
Карточку можно тащить за шапку, место запоминается.

**Пулы в списках GMGN.** Галка «в списках» в шапке карточки LP: у каждого
токена в трендах и новых появится метка «пулы $X · об ×N» — ликвидность пулов и
во сколько раз её прокрутил оборот за сутки. Считается только то, что видно на
экране, по 30 токенов за запрос.

**Скринер пулов.** Кнопка «топ ↗» в карточке LP (или «скринер пулов ↗» в ⚙)
открывает вкладку: топ токенов Robinhood по обороту, разобранный для LP, с
сортировкой по доходности у цены, фильтром падающих и минимальной ликвидности.
Каждый разбор запоминается — через сутки видно, растёт ли ликвидность людей.

**На графике:** ступени леддера (прямо из цепи, по номерам позиций), мешок
токена и доля выпуска, фисы в штуках (токен и стейбл), линия безубытка всей
сумки и точки прошлых сборов с причиной — памп, тейк, у верха или руками.

## Меню

Кнопка расширения на панели Chrome открывает все настройки в одном месте:
сторож (главный выключатель, автосбор у верха и низа, памп, порог, частота),
GMGN (карточка LP, пулы на графике, метки в списках, холдеры), окно на Liquidity
Ladder и узлы RPC. Изменения применяются сразу во всех вкладках.

## Установка

1. Скачать папку целиком.
2. `chrome://extensions` → включить «Режим разработчика» → «Загрузить
   распакованное расширение» → выбрать папку.
3. Открыть Liquidity Ladder, кликнуть по пулу — появится окно с графиком.

## Что нужно от тебя

**Свой RPC.** Расширение читает глубину пулов прямо из цепи, и для этого нужен
узел. Впиши его адрес в ⚙ → «RPC сети». Подойдёт бесплатный ключ Alchemy,
QuickNode или любого другого провайдера. Ключ хранится только в твоём браузере
и никуда не отправляется.

Без RPC работает всё, кроме глубины пула и цен для сторожа.

**RPC для чтения (необязательно).** Быстрый узел только для чтения цены и
ликвидности пулов — это почти все запросы. Например, бесплатный OrbitFlare:
`https://robinhood.rpc.orbitflare.com?api_key=…` (до 10 запросов в секунду,
пачка до 100). События он отдаёт окнами по 10 000 блоков, поэтому пулы ищутся
через GeckoTerminal и узкие окна по времени создания пула, а не по всей истории.

## Сторож: как он устроен

Четыре повода, каждый включается отдельно. **По умолчанию выключено всё** — это
действия с деньгами, и включать их надо осознанно.

| Повод | Когда срабатывает |
|---|---|
| Импульс | цена выросла на N % за M минут и держится у пика |
| У верхней границы | цена подошла к верху леддера (своя галка) |
| У нижней границы | цена подошла к низу леддера (своя галка) |
| Уровни | цена пересекла заданную тобой цену или капитализацию |

Уровни задаются ценой или мкапом — понимает и запись GMGN (`0.0₄4523`), и
сокращения (`140k`). Действие на выбор: собрать комиссии или закрыть позиции.
Верхние края ступеней отмечаются галками, со смещением (например, за 10 % до
края).

Порог «не собирать меньше $N» ограничивает все поводы — мелочь не соберётся.

### Что он не делает

- **Не трогает твои вкладки.** Сбор и закрытие происходят только в собственных
  вкладках расширения — они живут в отдельной свёрнутой группе и закрываются
  сами. В твоих вкладках он только рисует график.
- **Не хранит ключей и не подписывает транзакции.** Он жмёт те же кнопки, что
  и ты. На встроенном кошельке сайт подписывает сам, на внешнем подтверждение
  придёт в кошелёк.
- **Не пользуется закрытым API сайта.** Открытого API у Liquidity Ladder нет,
  а повторять внутренние запросы вслепую — гадание: формат поменяют, и всё
  сломается молча. Действия идут через кнопки на странице.

## Сети

Robinhood Chain (Uniswap V4). Остальные сети сайт поддерживает, но глубина
пулов и сторож считались и проверялись только на Robinhood.

## Разработка

```
npm install     # только jsdom, для тестов
npm test        # 197 тестов
```

Сборки нет: это обычные файлы, Chrome грузит их как есть.

Тесты стерегут то, что молча ломается и руками не ловится: вызовы
несуществующих функций, пропавшие узлы разметки, настройки, которые не
доезжают до сторожа, ключи токенов в разном регистре, целостность сообщений
между страницей и воркером.

## Журнал и повторы

Ошибки воркера, сторожа и страниц пишутся в один журнал: значок расширения →
«Журнал». Там же кнопки «скопировать» и «очистить». Ключи из ссылок
вырезаются. Свап, который не прошёл (газ, проскальзывание, молчание узла),
повторяется до 3 раз с паузами 5, 12 и 25 секунд; можно задать, на сколько
процентов поднимать проскальзывание на каждом повторе.

## Версии

Каждая версия сохраняется в git коммитом с тегом `vX.Y.Z`.

```bash
./tools/release.sh 3.12.0 "что изменилось"   # тесты → ключи → номер → папка Chrome → коммит и тег → GitHub
./tools/secrets-check.sh                     # отдельно: нет ли ключей в файлах репозитория
./tools/rollback.sh                          # список сохранённых версий
./tools/rollback.sh 3.10.0                   # поставить в Chrome старую версию
```

Если тесты падают, версия не сохраняется и в Chrome не отправляется. Откат меняет
только папку, которую грузит браузер: исходники и история остаются как были.

Перед коммитом релиз ищет ключи: ключи узлов и API, токены GitHub, приватные
ключи и дословные значения из личных `.env` (`lp-screener/.env`,
`pons-autolaunch/.env`). Нашёл — версия не сохраняется и никуда не уходит.
Ключи в расширении живут только в `chrome.storage`, в файлах их быть не должно.

Два репозитория. Приватный `lokert31/gmgn-holder-entries` — полная история
версий. Открытый `lokert31/gmgn-ladder` — тот же код без истории разработки,
коммиты от скрытой почты GitHub; туда же уходит zip расширения в Releases.
Релиз делает оба шага сам, `./tools/publish.sh X.Y.Z "что изменилось"` —
отдельно. Сеть подвела — версия всё равно сохранена локально,
догнать: `git push --follow-tags`.

Поставить расширение из релиза: скачать zip, распаковать, `chrome://extensions`
→ «Режим разработчика» → «Загрузить распакованное» → выбрать папку с
`manifest.json`. RPC-узел вписывается в настройках расширения, в коде его нет.
